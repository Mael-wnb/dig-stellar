## 4. Ops redaction (local)

A step row whose message contained a URL with a key-like path segment was inserted directly into
the local `refresh_step_runs`, read back through both public endpoints, then deleted.

```text
### C1 seed a step row whose message carries a URL with a key-like path (local DB only)
sec-g1-drill|request to https://rpc.example.com/v1/AbCdEf0123456789AbCdEf0123456789AbCdEf01 failed, reason: socket hang up
INSERT 0 1

### C2 GET /v1/ops/metrics -> step message redacted
[{'step': 'sec-g1-drill', 'lastRunAt': '2026-10-27T17:09:48.487Z', 'lastStatus': 'FAILED', 'lastDurationMs': 1, 'lastMessage': 'request to https://rpc.example.com/[redacted] failed, reason: socket hang up', 'failures24h': 1}]

### C3 GET /v1/ops/status -> segment message redacted
key present anywhere in payload: False
message: request to https://rpc.example.com/[redacted] failed, reason: socket hang up

### C4 remove the seeded row
DELETE 1

```

The write-side half (`apps/indexer/src/lib/redact.ts` in the refresh orchestrator) applies the
same rules before a message is persisted; the read-side half above covers rows written earlier.
